| 1 | **Do not bet batch 4 on skill `paths`**. Test first: one skill with `paths: "**/*.cs"` → `/skills` lists it? Read a `.cs` → `/context` shows the body? If either fails, fallback ladder: (a) `rules/*.md` with `paths` (docs-confirmed, cheap facts); (b) PreToolUse `Read\|Edit\|Write` command hook that globs `tool_input.file_path` and returns `additionalContext` naming/injecting the skill (workaround in #62049); (c) description with file-type keywords, no `paths` | #49835, #62049, memory.md | all 9 `K + paths` skills, `evals/skill-triggering.md`, `validate.mjs` | reliability: avoids 9 skills becoming invisible | **C** |

## 3. Known pitfalls by feature (as reported; verify on 2.1.306)

| Feature | Pitfall | Source | Mitigation in kit |
| --- | --- | --- | --- |
| skill `paths` | skill undiscoverable / never auto-loads; unquoted globs sometimes register where quoted ones don't | #49835, #62049 | §2 row 1 ladder; validator forbids `paths` on skills until the smoke test passes |
| rules `paths` | YAML list and quoted single value ignored (CSV parser), comma string works; rule with unparsable YAML silently loads **always**; symlink/subdir/`--add-dir` variants not loaded; compaction summarizes them away; user-level rules load before project rules, conflicts unresolved | #21858, #22170, #17204, #16853, #57934, memory.md | emit `paths: "a,b"` strings; `validate.mjs` parses YAML and fails on error; ≤ 25 lines facts only |
| `context: fork` | ran inline on some versions (#16803, #21725, #49559 — closed resolved); fork sees **no** history → skill must be self-contained; a *backgrounded* fork loses `Agent` (#88453, closed not planned) → `background: false` already in spec; fork mode default means results arrive async | issues, sub-agents.md | spec covers `background: false`; add "no history" check to skill-forge; verify UX (§2 row 16) |
| agent `memory` | dead with explicit `tools:` lacking Write/Edit; off when auto memory off; project scope resolves against launch cwd; agent may do the memory write instead of the task | #57507, #82545, #55648 | §2 row 3 |
| prompt hooks | not on SessionStart; default model = background model; 30 s timeout; evaluator sees only the hook input/transcript, not the repo; Stop loop risk → `stop_hook_active`, 8-continuation cap, `impossible`; agent hooks 2–30 s + thousands of tokens per event | hooks.md, community | §2 row 10 two-tier design |
| workflows | ultracode fan-outs drain 5-hour windows; per-run token caution; `Date.now()`/`Math.random()` throw in scripts; resumed runs re-run everything after the first changed agent | workflows.md, #66762 | `small`, saved scripts only, no ultracode |
| autoMode | lists without `"$defaults"` replace built-ins; project/local `autoMode` ignored; `allow` entries override `soft_deny` (additive, not a boundary); prefix allow rules still bypass the classifier unless `classifyAllShell` | auto-mode-config.md | §2 row 2; keep hard limits in `permissions.deny` + hooks, not in the classifier |
| `disable-model-invocation` | unstable across versions: still listed (#31935-era), hides from model entirely (#87536 regression), breaks `/name` (#78523), absent in coordinator mode (#82237); no effect on plugin skills | issues | prefer `skillOverrides: name-only` for grill-me/worklog-class skills; keep a `/name` smoke test in evals |
| skill listing budget | descriptions dropped silently when > 1 % of window; least-used first; `/context` Skills row was wrong before 2.1.196 | #64606, skills.md | §2 row 7 |
| `maxTurns` | reported unenforced on subagents (#41143, 72 turns with `maxTurns: 10`, closed) | issue | treat as advisory; validator should not *require* it |
| subagents | each starts cold (own cache, 5 m TTL unless `subagentPromptCacheTtl`), re-reads files the parent read; 15 k-token description warning | sub-agents.md, prompt-caching.md | brief carries file list + output contract; `1h` TTL only for fan-outs |
| statusline | `current_usage` null before first call and right after `/compact`; `used_percentage` input-only | statusline.md | null-safe cache file (§2 row 5) |
