# Delivery flow "two colleagues" — W1–W15 and three principles

Source: the owner's model ("a team: interpret, ask when in doubt, implement, test, review against the request and for
quality, loop until right, then decide together who tests locally; out of scope is discussed, never done") and a
three-way debate (quality lens, cost lens, the owner's advocate), 2026-10-24. Supersedes N1 of
`2026-10-24-flow-n1-n6.md` (one task per run): measured, a run costs a fixed ~350k subagent tokens whatever its size
(4 tasks in one run: ~160k per task; 1 task per run: ~470k), so one run per coherent request is cheaper.

Verify: `bash -c 'node --test tools/*.test.mjs' && node tools/validate.mjs`.

## Principles

- **P-run** one `impl-review-loop` run per coherent request: one implementer works through every plan task in
  order, testing after each; reviewers read the whole diff once. Split only past ~15 files or for areas that share
  nothing (different reviewers, different verify).
- **P-size** every check scales with S/M/L (table below); S keeps CLAUDE.md "the approach in one line, then go".
- **P-weight** a doubt or a choice reaches the owner only when it weighs: it changes what the owner sees or uses,
  touches a contract (API, event, schema) or data, costs or risks something, or goes against an owner decision.
  Anything else (internal names, code order, style details) is decided by the agents and not reported.

| Check | S | M | L |
| --- | --- | --- | --- |
| W1 criteria | one line in the approach message, no wait unless it asks | 3–5 lines, owner ok | criteria + proof + questions, owner ok |
| implementation | inline | 1 implementer | 1 implementer, all tasks |
| reviewers round 1 | 1 Sonnet | 1 Opus | Sonnet + Opus (+ specialists when touched) |
| W6 intermediate delta rounds | — | finders + 1 Sonnet medium | finders + 1 Sonnet medium |
| W6 final full read | — | only if a fix ran | only if a fix ran |
| W5 preview | screenshot in the verdict when visible | when visible | when visible |
| W7 cleanup + re-review | — | yes | yes |
| W10 proof check | — | yes | yes |

## Tasks

- [ ] **W1 criteria with their proof** (`skills/deliver`): step 1 states acceptance criteria and, per criterion,
  the proof and what it asserts (automated test; else run the thing: browser screenshot, HTTP call, read-only query,
  CLI output; else "the owner tests"); scaled per the table. Replaces N1's "one plan task per run" text with P-run.
- [ ] **W2 the owner's words to reviewers**: workflow arg `request` (the owner's messages, verbatim) beside `brief`,
  given to the round-1 reviewers and the final full read; `code-reviewer.md` pass E checks the change against both;
  a brief that departs from the request is a finding routed to the owner as a `question`, never to the fixer.
- [ ] **W3 decisions ledger**: workflow arg `decisions` (each the owner's words, one line, only those touching the
  perimeter) given to implementer, fixer and every reviewer; an edit contradicting one is routed as a `question`.
- [ ] **W4 defaults**: implementer and fixer output `defaults: [{ choice, alternative, path }]` for non-trivial
  choices the brief did not state (P-weight); no stall; the workflow returns them and `deliver` lists them in the
  verdict. Weighty ones stay `questions`.
- [ ] **W5 preview**: for M/L with owner-visible output, after round 0 the workflow stalls `question` with what to
  show (the caller takes the screenshot/sample and asks); the verdict carries a final screenshot of the same surface.
  No new stall kind.
- [ ] **W6 reviewer selection**: round 1 the full panel by size; intermediate delta rounds only the reviewers that
  raised the open findings plus one Sonnet at medium effort; the round that would return OK runs the full panel once
  on the cumulative fix diff since round 1, skipped when no fix ran. On M the full panel is the one Opus.
- [ ] **W7 cleanup re-review** always runs, on Sonnet at medium effort.
- [ ] **W8 growth in review**: the reviewer prompt carries, per touched file, lines at start → now (+%) from
  `git diff --numstat <start.head>` and a line count; pass G: past 600 lines or +30% → a P3 split proposal to the
  closing table, never auto-fixed.
- [ ] **W9 proofs after review**: the matrix runs on the final code (already so; the docs say why).
- [ ] **W10 proof check**: before the verdict the main session reads only the assertion lines of each criterion's
  proving test (+ the hunks behind `defaults` and any ledger contradiction); a proof that cannot fail on the old code
  is `non verificato`. `code-reviewer.md` pass E: a vacuous test named as a criterion's proof is P2.
- [ ] **W11 done-claim** reads the transcript backward in 512 KB chunks to the turn's start (cap 8 MB); still cut →
  block once asking for the verdict table (fail closed).
- [ ] **W12 findings log**: the workflow appends one JSON line per run to `<git-dir>/deliver/findings.jsonl`
  (`{ at, run, size, rounds, minutes, findings: [{ category, priority, path, closed }] }`, no agent call);
  `session-brief.js` adds one line when a category recurs 5+ times since the last retro or a file holds 3+ open
  P3s; `skills/retro` reads this log, proposes at most 5 implementer-rule lines, the owner approves.
- [ ] **W13 owner-only acceptance**: `accept` of a P1/P2 risk comes only from the owner (loop.md: "apply the
  defaults when the owner said not to be asked" covers `questions` only); a scope revert of a hunk the owner asked
  for in their own words becomes a `question`.
- [ ] **W14 local test line**: the verdict ends with "Test locale: proposta <who/what>"; the owner decides.
- [ ] **W15 constraint**: no new hook, no new `stall.why`; every addition is an arg, an output field, a prompt line
  or an existing stall. The `not-converging` stall and the cleanup pass stay.
