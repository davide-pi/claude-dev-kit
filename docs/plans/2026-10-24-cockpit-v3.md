# Cockpit v3 — always-visible header, four tabs, system monitor, session data

Branch `feat/cockpit-v2` (worktree `claude-dev-kit-cockpit`). Source: the owner's brief (Desktop `tmp.txt`, 2026-10-24),
a feasibility study against the engine types, the mockup "cockpit v3" on the design canvas. v2 (tabs Sessione,
Agenti, Lavoro, Repo) is the starting point: reuse its code, move it, never rewrite what works.

Files: `mods/cockpit/hooks/*`, `mods/cockpit/types/index.d.ts`, `mods/cockpit/tests/*`, a new
`mods/cockpit/sysmon/sysmon.mjs` (Phase 5), `statusline.js` + `tools/statusline-cockpit.test.mjs` only for the
cleanup and the worktree icon, `README.md` (Cockpit section).

Verify (every phase): `claude plugin test mods/cockpit` → 0 fail; `claude plugin validate mods/cockpit`;
`node --test tools/statusline-cockpit.test.mjs`; at the end `bash -c 'node --test tools/*.test.mjs' && node tools/validate.mjs`.
Engine types: `~/.claude/mods/cockpit/.claude-plugin/types/claude-code/index.d.ts` (read-only).

Rule for every datum: free (hooks, `session.usage()` without breakdown, local files) unless the owner presses a
button; a datum the engine does not give is left out, never faked.

## Phase 1 — layout, header, refresh tiers, buttons

- [ ] **T1 layout.** Content width `min(bodyColumns, 60) − 2`, one column of margin left and right always
  (`paddingX` 1); everything truncates or wraps to that width; tests at 40, 58, 80 columns.
- [ ] **T2 header, always visible above the tab bar.** Line 1: model, effort, Claude state icon (derived: `turn.start`
  → working, thinking chunk → thinking, a `tool.call` in flight → tool (name), permission request/notification →
  waiting, main `turn.complete` → idle), session cost and last round cost. Line 2: folder icon by kind
  (`nf-md-folder` U+F024B plain folder, `nf-md-source_repository` U+F0CCF repo, `nf-md-source_repository_multiple`
  U+F0CD0 linked worktree), branch with ↑↓ and the compact git state. Then context bar, 5h and 7d credits (v2 rows,
  burn line), cache hit of the last turn coloured (≥ 80 % green, 50–79 amber, < 50 red), autocompact forecast
  `~N richieste` (threshold from `usage({ breakdown: 'summary' })` read once, average context growth of the last 5
  main turns; absent with fewer than 2 turns). statusline.js uses U+F0CD0 for a worktree too.
- [ ] **T3 refresh tiers.** Three timers — fast 2 s, medium 10 s, slow 30 s — plus hooks; the fast and medium ones
  run only while a tab that needs them is selected (Subagenti elapsed time 2 s, Sistema 2 s/10 s); git on
  `turn.complete` + medium; PR and done-claim log slow. Replace the single 15 s tick.
- [ ] **T4 buttons at the bottom.** `compatta` and `segna ore` on the last row of the pane height
  (`props.scroll.bodyRows`, a column box of that height with a growing spacer); when the content is taller they
  follow it. Tested with a short and a tall tab.

## Phase 2 — Subagenti tab

- [ ] **T5** per agent: state, type and description, model (+ asked→got warning), effort, tokens in / out / cache
  (the four counters kept, live per step), elapsed time, share of the session's tokens (D1), the tool running now
  (`tool.call` before/after `next`) or the last one; history collapsed, press opens the transcript (v2).

## Phase 3 — Contesto tab

- [ ] **T6** breakdown bar and table by category from `usage({ breakdown: 'summary' })` (free, local estimate), read
  when the tab opens and after `turn.complete` (debounced); a `conteggio esatto` button runs `full` (costs
  token-count requests, so only on press).
- [ ] **T7** top 5 static consumers (memory files, MCP tools, agents, skills listing), the skills invoked this session
  (hook `skill.prompt`) and the listing count.
- [ ] **T8** context sparkline per round (tokens at each main `turn.complete`, last 20) and the hint
  `conviene compattare` when context ≥ 70 % and the last 3 rounds grew more than 5 % each, or the forecast is ≤ 3.

## Phase 4 — Lavoro tab

- [ ] **T9** changed files with +/- (v2 Repo code) pressing opens the diff pane; the todo list with its bar (v2).
- [ ] **T10** last 8 tools/commands of the main thread (ring buffer from `tool.call`: tool, short argument, outcome,
  time).
- [ ] **T11** the PRs of this chat: every PR seen for the branch or created in the session (`gh pr create` / `az repos
  pr create` output caught in `tool.call`), with state and checks, as `Link`s; persisted with the session (T15).
- [ ] **T12** timesheet: worklog days pending / under target (v2 badge), the session's active time today when the
  engine's numbers are at hand; `segna ore` stays the only action that spends tokens.

## Phase 5 — Sistema tab (only while selected)

- [ ] **T13** one persistent child (`$.process.spawn` of `node mods/cockpit/sysmon/sysmon.mjs`) started when the
  tab opens, killed when it closes, one JSON line every 2 s: CPU % (os.cpus delta), RAM, network rate (`netstat -e`
  delta); every 10 s the session's child processes (CIM Win32_Process by parent, from the Claude pid in
  `~/.claude/sessions/<pid>.json`) with their listening ports (`netstat -ano`); every 30 s disk free
  (`fs.statfs`); once the power source (Win32_Battery: battery % and charging, or wired).
- [ ] **T14** the view: four compact rows with sparklines (CPU, RAM, net) and the process/port table (max 6).

## Phase 6 — alerts, quick note, session data, docs

- [ ] **T15** session data file `~/.claude/.cache/cockpit-data-<session>.json` (history, PRs, notes, context samples),
  kept while `~/.claude/projects/*/<session>.jsonl` exists (sessions are kept `cleanupPeriodDays`, 90 days); the
  hourly prune in statusline.js deletes a data file whose transcript is gone; `cockpit-<session>.json` stays the
  3-day handshake for the status line.
- [ ] **T16** alerts (D4) through `$.ui.toast`, deduplicated per episode.
- [ ] **T17** quick note: an `Input` (2 rows) under the tabs, saved in the session data; `invia` puts it in the prompt
  box (`prompt.fill`, append — D3).
- [ ] **T18** README Cockpit section and full gate; install only when green.

## Excluded, and why

| Item | Why |
| --- | --- |
| Temperature | Windows exposes it (MSAcpi_ThermalZoneTemperature) only to an administrator |
| Autocompact forecast in time | turn length varies too much; requests are a steadier unit |
| Top consumers per message | the engine reports Messages as one total, not per message |
| `breakdown: 'full'` automatic | it spends token-count requests on every read: only on the button |
| `Get-NetAdapterStatistics`, `Get-NetTCPConnection`, a `pwsh` per tick | 1–2.5 s each; `netstat` and one persistent child cost ~40 ms |
| Workflow name in Lavoro | the engine does not expose a running workflow's name |
| `$` cost per subagent (D1) | needs a price list kept in sync by hand; share of tokens carries the same signal |
| Note sent with `prompt.submit` (D3) | starts a model turn on its own; `fill` lets the owner decide |
