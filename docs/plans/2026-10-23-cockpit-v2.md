## Phase 2 — tabs

- [x] **T7 tab bar.** Four `Button`s: `Sessione`, `Agenti <n running>`, `Lavoro <● when something needs attention>`,
  `Repo`. The selected tab lives in the mod state (default Sessione, kept across reloads in the state file); press
  switches. Verify: pane test, a press on `Agenti` draws the Agenti view.
- [x] **T8 Sessione view.** Header, folder/branch grid, ALM, CONTESTO (+ N2: at ≥ 80 % a red warning line, no button),
  CREDITI, the **running** agents (compact, max 5 rows, owner request). Buttons (N1, reworked on owner request): the
  very last row of every tab, under a rule: `compatta` always (`$.session.compact({ instructions })`, K8) and `segna ore`
  (owner request, reworked): it logs the hours of THIS chat, running `/worklog oggi sessione <id>` (`<id>` = `$.session.id()`
  at the press; the worklog skill supports the `sessione <id>` scope and asks the user when it cannot find an item) through
  `$.command.run`, the engine's documented way to run a slash command (its types: "Runs a slash command as if the person typed
  `/command args`"). Always shown while the session has an id, whatever the branch, a detached HEAD or no git: it is no longer
  tied to a branch, a work item id or a PR. No quick-buttons row, no `copia branch`, no `compatta ora`. Verify: pane tests per
  element, the row last on each tab, the row fits 40 columns, the command on a feature branch, a work item branch, the default
  branch, a detached HEAD and without git, no button between two sessions.
- [x] **K8 compaction instructions.** `compatta` tells the summary what to keep: the pure `compactInstructions(snapshot)`
  in `format.ts`, Italian, ≤ 400 characters: the fixed sentence (`Tieni: task in corso, decisioni prese con l'utente e il
  loro perché, …  Butta: output di tool già riassunti, tentativi superati.`) plus, when known, the open task titles
  (max 3) and the active deliver perimeter of the branch (entry count + first 2, read from
  `<git-dir>/deliver/perimeter.md`: `status: active` and its `branch:` the current one). A part that does not fit is left
  out. A running workflow's name comes from the engine's classic `Stop` / `SubagentStop` hooks (`background_tasks[].name`
  of a `workflow` task): the mod keeps the last stop's reading in the snapshot (cleared by a stop that reports none), so it is
  an end-of-turn snapshot, not live (`$.agent.list()` leaves a workflow's agents out). Verify: format tests with and
  without tasks/perimeter/workflow; pane tests, the press calls compact with the text (perimeter of another branch not
  named; workflow named until a stop reports none).

## Phase 4 — Lavoro, per agent (owner request)

- [x] **T11 main agent block.** `PRINCIPALE`: deliver perimeter (K5: `branch:`/`status: active` entries from
  `$(git rev-parse --git-dir)/deliver/perimeter.md`, file count, and the changed files outside it, computed like
  `scope-guard.js --check` against HEAD), the session tasks (moved here from the main view), worklog warnings.
  Verify: pane tests with a perimeter file in a temp repo.
- [x] **T12 workflow progress (K4).** For a running `impl-review-loop` (or any workflow): name, phase, agents done/total
  from what the engine exposes (agent list / task events); round and P1/P2 counts only if exposed, else omitted.
  What the engine exposes is the workflow's name (classic `Stop` / `SubagentStop` `background_tasks`) and its agents' spawns
  (`agent.spawn` carries `workflow.runId`) and `turn.complete`s: the block shows `WORKFLOW · <name>` and `agenti <done>/<started>`
  (total = agents seen starting so far, the script spawns them as it goes). Phase, round and P1/P2 counts are not exposed
  (no event, no list row carries them): left out, not drawn. A main-loop `Stop` reporting no workflow ends the run, and with it the run's agents still running: the engine never lists
  them, so a tick does not end them, only their own `turn.complete`, an explicit failed/killed listing or the run's end does. Verify: pane
  test with a mocked running workflow.
- [x] **T13 subagent blocks.** One block per running subagent: type, its description (the spawn's `description`),
  last tool used (from tool events carrying its `agentId`) and elapsed time. Verify: pane test.
- [x] **T14 hook triggers (N3).** Last 3 entries of `~/.claude/.cache/done-claim.log` (time, rule, short text); other
  hooks that log later can be added the same way. Verify: pane test with a fixture log.

## Phase 5 — Repo

- [x] **T15 branch and changes.** Branch, upstream ahead/behind (from `status -b`), commits since the default branch
  (`origin/HEAD`'s), changed files with `+/-` (numstat, binary as `bin`, untracked as `?`), max 8 rows then `… +n`;
  worktrees list. Read on the 15 s tick, but only while the Repo tab is selected (and at the press that selects it).
  Verify: pane tests with a stubbed git.
- [x] **T16 diff on press.** Pressing a changed file opens a second pane `cockpit-diff`, titled `diff · <file>`, drawing
  `git diff HEAD -- <file>` (untracked: the whole file as additions) with the engine's `Code` element, `format: 'diff'`;
  closable (its own `chiudi` button, the engine's close mark). A diff over 90000 characters is cut before a hunk and says
  so; a diff with no hunk (binary) says so. Verify: pane tests, the press opens the pane with diff hunks.
- [x] **T17 PR and checks.** For the branch: the PR (`gh pr view --json` on GitHub; `az repos pr list` on Azure DevOps
  with the org of the ALM line, never the CLI's default), state, review, checks; read at most every 5 min, in the
  background, never blocking a render; absent when no CLI or no PR. Azure DevOps lists no checks: none are claimed there.
  The default branch is not asked. Verify: pane tests with a stubbed result.
