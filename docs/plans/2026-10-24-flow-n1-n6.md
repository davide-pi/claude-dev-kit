# Delivery flow N1–N6 — task-sized runs, convergence instead of caps, P3 cleanup, questions

Source: the owner's review of 2026-10-24 (cockpit v3 phases 4–7). Measured: the implement step took 131 / 23 / 24 min
(phases 4, 5, 6) against 6–11 min for all reviews and 2–7 min for fixes; the tool budget was raised twice; 18 P3s of
phase 7 were left open; implementer doubts were settled by defaults the owner never saw.

Files: `workflows/impl-review-loop.js`, `tools/impl-review-loop.test.mjs`, `agents/implementer.md`,
`skills/deliver/SKILL.md`, `skills/deliver/references/loop.md`.
Verify: `bash -c 'node --test tools/*.test.mjs' && node tools/validate.mjs`.

## Tasks

- [ ] **N1 one task per run.** `deliver` (SKILL.md, loop.md): an L change is launched one plan task (or one cluster of
  tasks touching the same files) per `impl-review-loop` run, sequentially in the same worktree, committing between runs.
  The implement prompt loses its tool-call budget text (`IMPL_BUDGET`); the reviewer and fixer budgets stay (their
  work is bounded by the findings).
- [ ] **N2 targeted tests.** Implementer prompt and `agents/implementer.md`: while working, run only the test files
  the change touches (and the one seen failing); run the `verify` command once, at the end, before reporting.
- [ ] **N3 convergence instead of the fix-cycle cap.** `decideRound`: drop `FIX_CYCLES` / `capLimit` / the `cap`
  stall and `continue`; a fix round that closes none of the findings it was sent (while `toFix` is non-empty) is a
  STALL `no-progress`. `churn`, `no-verdict`, `disputed` stay. A resolution `continue` from an old caller is ignored.
- [ ] **N4 P3 cleanup pass.** When a round would end DONE and `minor` holds P3s inside the perimeter (not `scope`, not
  `causedByChange: false` outside the files), one FIX pass on them, then one review of that delta (its new P1/P2 go
  through the normal loop, its P3s are reported, never a second cleanup). P3s outside the perimeter stay in the
  table.
- [ ] **N5 questions.** The implementer's and fixer's structured output gains `questions: [{ text, default, why }]`
  for a behaviour choice the owner would see (not an internal one). Any question → STALL `question` before review,
  carrying them; the caller asks the user (or, when the user said not to be asked, applies the default and lists it
  as an open decision) and resumes with `{ round, answers: [{ text, answer }] }`, which reach the implementer as
  guidance. `deliver` documents it.
- [ ] **N6 visual check** (cockpit only, done in the cockpit plan): not part of the kit flow.
